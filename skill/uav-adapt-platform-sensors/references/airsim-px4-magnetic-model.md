# AirSim / PX4 地磁模型适配

## 目标与适用条件

让 AirSim 生成的磁力计测量与目标 PX4 使用的地磁参考一致，同时保留机体旋转、噪声、偏置和延迟等传感器语义。先查明差异，不能仅凭航向偏移、解锁失败或磁场告警就判定模型不一致。

本技能处理仿真平台传感器层，不改规划算法、ROS 世界原点或控制链来抵消磁场误差。只读诊断、源码修复、构建部署和飞行验证分别按用户请求执行；整理方案不意味着可以启动飞机或替换运行中的仿真器。

## 先定位实际运行链

核查目标工作区约定，记录 UE 工程/打包场景、实际加载的 AirSim 插件、AirLib 来源、PX4 源码提交与二进制、容器镜像 ID、启动脚本和有效参数。源码与产物必须分别追溯；插件目录存在补丁不证明运行 DLL 已包含补丁。

沿实际链路检查：AirSim 环境经纬度 → 磁场参考 → 机体磁力计 → MAVLink HIL_SENSOR 或目标版本使用的传输 → PX4 sensor_mag/vehicle_magnetometer → EKF。ROS 磁场话题存在不能证明 PX4 已使用同一测量。

对比 AirSim 模型和 PX4 实际链接的模型，包含版本/表内容、经纬度与高度处理、磁偏角、磁倾角、强度、插值边界、单位和坐标。确认 AirSim/GPS 与 PX4 地磁查询使用相同地理位置。保存参数实际值，不只检查脚本中导出的环境变量。

## 实施模型统一

确定是模型差异后，读取 [模型实现与历史案例](magnetic-model-integration.md)。优先把锁定 PX4 的地磁表和查询逻辑接入 AirSim 的磁场参考生成处；已有兼容实现时先核对版本和实际启用分支，避免重复补丁。

- 同时匹配磁偏角、磁倾角和强度，不能只加固定 yaw 修正或调整 NoiseSigma。
- 世界磁场先按目标约定生成，再由真实姿态转换到机体；噪声、偏置、比例与时间处理保留在原传感器层。真值姿态用于生成仿真测量属于模拟器实现，不得转为 EKF 的理想姿态输入。
- 不以关闭磁融合、屏蔽检查、放宽创新阈值或强制解锁作为模型修复通过的依据。其他航向源可以作为单独声明的部署选择。
- 参数枚举、位掩码和默认值按目标 PX4 提交解释；历史参数数值不能跨版本照抄。

修改实际构建输入，记录基线与补丁并保留来源和许可证。重编受影响的 AirLib/UE 插件及必要场景产物，核实构建复制链；无需因此默认重建 PX4 或团队共享工具镜像。磁场修复在插件中时，只复制地图 .umap 或 settings.json 无法迁移修复。

## 验证与交付

读取 [验证与交付](magnetic-model-validation.md)，按请求覆盖数值对照、构建产物、实际测量和 EKF/动力学验证，并分别报告状态。未执行项保持待验证；旧场景能飞不等于新版模型已独立验收。

交付模型来源及版本锁、补丁/构建入口、有效传感器和 PX4 参数、数值对照、运行产物身份、测量与 EKF 日志索引、适用范围和缺口。正式说明使用仓库相对路径或可配置路径，不依赖某台机器的历史绝对路径或被忽略的日志才能理解。

迁入 Aerohub 时，平台接入/构建归 `simulator/airsim/`，跨角色编排归 `deployment/`，验收原始证据归 `log/`；遵守目标仓库自身约定。确需修改 AirSim 上游源码时，以 Fork 子模块记录可获取的提交，不以临时构建补丁替代最终来源。本技能可以独立使用；已有平台适配、构建和端到端技能时按各自职责配合，不复制相互冲突的规则。
