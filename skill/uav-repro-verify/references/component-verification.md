# 组件验证与交付结论

本规则承接已拆分的跨阶段迁移流程中的验证部分。

## 验证 Harness

运行前按 [验证 Harness](validation-harness.md) 声明适用测试、门槛、场景和证据目录。运动组件统一使用有屏 AirSim + PX4 SITL；构建、合成输入、数据集和进程存活只作为对应层级证据。

依次验证接口、真实平台输入、下游消费、正常任务、边界、故障、恢复和资源清理。状态权威切换遵循预声明安全门；门失败时保留未执行与总体未完成状态。

**完成门：** 全部适用项在同一实现版本上执行并有可核查证据；任何失败、跳过或缺证据均保留，成熟度停在此前实际通过等级。

## 交付迁移结果

交付核心与 Harness 包、launch/配置、接口说明、运行与停止入口、健康条件、测试矩阵、证据索引和限制。复现结束后回顾过程记录，只把本轮证实且可复用的经验更新到正式 Skill。

## 证据记录器的真实消息回归

飞行前用目标 overlay 的真实生成消息驱动记录回调，并实际写盘、读回关键事件和失败结果。固定长度 PX4 float 数组可能返回 NumPy float32，直接 list 不会转成 Python float；Mountains 记录器因此在最终 JSON 序列化失败。边界处逐元素转 float 已通过真实 TrajectorySetpoint 回调回归。该测试不需要发布、解锁或仿真，也不证明飞行成功。

结果先于节点销毁落盘，销毁异常逐项记录；宿主保存短生命周期 probe 的 stdout/stderr，避免容器自动删除后只剩 CalledProcessError 而丢失原始原因。
