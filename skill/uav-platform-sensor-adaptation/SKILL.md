# 平台传感器与算法输入适配

## 职责与分层

目标是让平台实际输出的测量满足算法的输入契约，而不仅是话题类型匹配。读取项目约定、平台版本、传感器配置、实际发布代码和算法消费者；不得仅按组件名称决定适配方式。

- 平台驱动或传感器桥负责对接设备 SDK、AirSim RPC、PX4 数据通道，输出有明确语义的测量。
- 算法输入 Adapter 负责必要的格式和坐标转换；共享处理尽量复用，特有预处理留在算法边界。
- 状态估计与感知算法都可直接消费测量。Tool、Planner 也可订阅明确的数据接口，不必经过 Behavior；避免各自重复实现平台 SDK 接入。
- 状态估计输出自身状态，环境感知输出地图、点云或检测结果，两者可由同一算法产生，但应分别提供给对应消费者。不强制统一所有地图表示。
- 运动控制继续通过 AS2 控制/平台层到 PX4；传感器数据不要求全部绕经 PX4，也不允许用 AirSim 运动 API 绕过飞控来完成运动验收。

## 与已有 Skill 的边界

本 Skill 决定“从平台取什么数据、数据是否具备所需物理语义、如何进入算法”。ROS 发行版、消息生成、跨 ROS 传输和 QoS 的实现使用 [ROS 适配](../uav-ros-adaptation/SKILL.md)；AS2 插件发布与宿主生命周期使用 [AS2 接入](../as2-extension-integration/SKILL.md)；完整下游效果和故障验收使用 [端到端验证](../uav-sim-e2e-validation/SKILL.md)。不要分别维护相互冲突的时间、坐标或话题配置。

## 先交付数据契约，再实施转换

对每条输入记录以下内容，无法证实的项标为未知，并说明验证方法：

| 项目 | 必须确定的内容 |
| --- | --- |
| 来源与消费 | 传感器/平台版本、驱动或 RPC、实际发布者与话题、算法订阅入口；测量、滤波数据、估计状态或真值 |
| 字段 | 单位、类型、有效范围、缺失语义、协方差、二进制布局及算法实际读取的字段 |
| 时间 | 采样/积分/扫描起止/发布时刻、时钟域、延迟、频率与抖动、重复/乱序/暂停/reset 处理 |
| 坐标与标定 | ENU/NED、FLU/FRD、光学系、frame_id、外参方向、TF 权威发布者、内参/畸变及来源 |
| 传感器模型 | IMU 比力/角速度及处理历史；图像曝光与编码；雷达扫描模式、逐点时间、ring 和去畸变假设 |
| 可用性 | 丢帧、断连、重启行为、图形/算力要求、多机命名空间和数据源隔离 |

核查算法源码是否使用额外假设，如固定扫描角速度、同一 IMU 的积分结果、相机曝光时间。相同 ROS 消息类型和 PCL 转换成功不构成语义兼容证据。

## 选择最小适配

1. 优先复用平台、AS2 或已有算法的匹配接口与预处理器。仅名字相似不够，核对实际配置及实现。
2. 坐标、编码或字段可无损转换时，在 Adapter 显式实现并记录变换。改 frame_id 不能代替变换；改成 now 不能修复同步。已去畸变点云不得再按原始扫描假设重复去畸变。
3. 缺失信息不可凭空恢复：不制造扫描线、逐点采样时间、测量强度或协方差。算法允许的默认值须标为占位属性，并验证不会被误当作测量。瞬时整帧与旋转扫描分开处理。
4. 若现有接口无法满足，优先选择有证据支持的传感器配置或当前项目中的独立预处理／Adapter 入口。只有确实必须修改上游源码时才使用可追溯 Fork，并锁定基线和修改提交；构建补丁只能作为临时诊断或迁移工件，不能作为复现成功后的最终来源。说明语义损失与适用范围；不可验证的候选保持待验证，不为得到通过结果关闭算法必需输入。
5. 平台事实不可得时，继续可独立完成的接口检查；不能据未知条件宣称已接入。当前 AirSim 场景先读 [平台核查要点](references/airsim-px4.md)。

## 验证与交付

深度图接模型前，分别核查单位（`32FC1` 米或 `16UC1` 毫米）、端序、行 padding、零/非有限无效值、采集 stamp，以及训练相机 FOV。resize 只改变像素网格，不校正 FOV 或外参。可复用 `deployment/inference/tests/test_contract.py` 验证格式转换；该测试属于合成接口证据，不证明 YOPO 已消费真实 AirSim 相机或相机与规划系已经对齐。

官方发布的不同checkpoint可能对应不同仿真器与预处理。逐一核对其实际运行配置、
裁剪比例、相机pitch和深度来源，再计算裁剪后的视场；不能把同项目另一个模型的
相机参数直接套用。DiffPhys高速发布源码包含Flightmare相机配置及中心裁剪，而
swarm评估使用AirSim；去掉裁剪的全幅实验应单独命名，不因单轮导航改善就宣称等价。

对双目深度追踪匹配器输出类型、视差范围与亚像素支持、baseline和焦距、无效视差
编码、bf/disparity转换、整数毫米截断及最终发布话题。DiffPhys高速发布的
flightmare_bridge使用8位整数视差，0/255记无效，毫米mono16输出；Planner再转米并
将0替换24m。连续理想深度与其在单位上可兼容，但生成分布仍不同。分别量化毫米
传输和整数视差影响，不将理想深度量化或加噪声称为完整SGM复现。
若专项启用双目，记录两相机同步、实际基线、光轴深度/射线距离及额外采集时延；
普通单深度相机基线不因调查而默认增加无关采集。

FOV注释与渲染器文档不一致时，追踪中间桥的转换及深度反投影焦距。
Agile Autonomy的Flightmare桥将配置水平角转换成渲染器垂直角，两种约定可同时正确。
中心裁剪按源码整数取整，nearest按实际索引规则验证；若将点式归一化移过采样步骤，
用非均匀深度、无效值及连续模型输出证明等价。源CameraInfo保留原始几何，
模型张量的尺寸不反写为源标定。提高源分辨率后重新测量采集到消费的时延与唯一帧率。

复用其他Demo场景时，核对模拟器启用项、各容器采集进程和实际下游消费者三者。
没有点云消费者的视觉任务可在专属配置关闭LiDAR模拟与重复ROS读取；仅关闭相机
桥开关不会停止LiDAR。保留飞控必需传感器及任务必需输入，记录实际worker清单。

先用非恒等坐标、已知单位与时间样例验证转换和错误拒绝；再取实际平台消息，测量频率、时延、字段和同步。随后运行真实算法，确认输入被消费、输出有效并被实际下游使用。状态算法检查运动下的误差与漂移；地图检查运动下障碍稳定性和查询/规划消费。阈值在运行前按算法需求确定。

频率验收同时统计接收消息数和唯一采样时间戳数。平台桥可能高频重复发布同一状态；topic 工具显示的消息率不能证明控制获得了同等频率的新测量。重复 stamp 可按契约静默丢弃，倒序、未来或过期 stamp 应单独计数。多源状态组合还需测量配对误差，并证明组合后的 canonical 状态频率满足实际消费者 freshness。

源码审查、预处理测试、合成数据、实际平台采样、算法运行和运动闭环分开报告。真值只用于明确标注的评分或测试输入，不能偷偷替代待验收算法。GPU 是算法运行条件时必须执行真实 GPU 测试；GPU 暂时缺失只能使复现保持未完成，条件恢复后补测。当前开发主机已有 GPU，不得用关闭相机、NullRHI、CPU mock 或合成算法输出冒充实际平台验收。

交付数据来源与契约、桥接/预处理代码、参数与标定配置、启动入口、版本、复验命令、证据及未覆盖项。平台专用桥放 `simulator/airsim/`；算法专用适配按 `src/basic_function/state_estimator/`、`src/basic_function/perception/` 现有归属组织，联合算法不复制两份；跨组件编排放 `deployment/`。过程记录放 `skill/temp/<任务>/`，原始证据放 `log/`。能力卡片位于 `cards/`，按本次实际变动维护输入依赖与验证状态；不把个人机器信息写入正式 Skill。

## 低频图像与高频定位

图像采集时刻应匹配有界定位历史中的测量快照，而不是在每次规划 timer 上与最新定位比较。独立检查当前定位新鲜度、图像新鲜度和该快照的同步偏差；用图像5 Hz、定位50 Hz的回归验证正常帧间周期仍可规划，且过期图像会停止。YOPO 实际接入曾因比较最新定位而拒绝正常目标，修复采用历史匹配，未放宽50 ms偏差门限。

对针孔深度相机，用内参/画幅计算实际水平与垂直 FOV。训练网络的像素尺寸不自动代表训练几何；例如90°水平视场下160×96约为61.93°垂直视场。DepthPlanar 视轴深度与 DepthPerspective 射线距离分别核对。共置与 pitch-only 外参是特定首期接入约束，非零杆臂需另行处理，不能推广成所有相机的默认物理模型。

速度等测量依赖同采样时刻的动态 TF 时，消息可能先于 TF 到达。保留有界原始测量队列，在原新鲜度上限内重试变换；保持时间戳，不以最新TF或now替代。仅在输入确实陈旧、持续无法匹配或覆盖耗尽时收口。YOPO 实际失败的分项年龄曾为深度75 ms、位姿21 ms、已接纳速度300 ms；动态TF落后速度40 ms的真实ROS回归检出了直接丢弃策略，修复后通过。

若权威接口明确保证Pose和body Twist共享同一测量stamp，可用严格配对的权威姿态作坐标旋转，避免依赖重复动态TF流；先核对真实发布源码，不将这一约定套给任意话题。AS2当前`publishTwist`以同一stamp发布姿态，YOPO据此保持同一状态源并等待配对；其他固定父系仍需相应时间TF。即便有队列，TF持续不可用也必须保留失败事实，不能仅靠等待掩盖。

视觉策略接入不同仿真机体时，先保存起飞后原始深度并统计近场返回的空间分布，检查相机是否看到机体或桨叶。更换相机杆臂须同步场景配置、真实TF和算法校验并重新验收；不以遮罩近距像素冒充传感器几何等价。DiffPhys的官方SimpleFlight杆臂在本PX4场景出现近场返回，显式前移后单轮短程通过；这是平台特定证据，不能推广为统一相机位置或唯一故障原因。

## 视觉策略的地面距离与接管条件

无高度字段的策略也可能从深度图中的地面距离决定竖直控制。迁移时同时核对上游
接管高度、姿态、速度与相机杆臂；源 FOV、pitch 和张量尺寸一致，不能证明地面
在图中的分布一致。对同一原生场景做静态高度扫描，固定状态与目标，分别比较
理想深度和原版双目匹配深度；单独改变输入来源，保留原始图像、相机变换、
深度单位与输出向量。不要通过遮罩地面、修改重力或放宽姿态门限掩盖差异。

DiffPhys 高速发布包的静态 GPU 对照已观察到：同一权重在不同地面距离下可从正常
向上承重变为近零或向下推力，原版 SGM 未消除该现象。它说明需要验证接管条件，
不建立通用的可飞高度范围。静态图像重复推进 GRU 只是敏感性诊断，不能代替真实
连续观测或闭环飞行；首帧满足控制门也不能证明该高度可稳定飞行。

## 评分真值桥

评分用真值桥与飞行控制链隔离，并使用非恒等位置和姿态样例独立回归。NED/FRD 到 ENU/FLU 的轴交换、符号和航向零点必须与平台状态转换逐项交叉核对；不能因消息 `frame_id` 正确或静止点重合就认定转换正确。错误的真值桥不会影响算法飞行，却会系统性扭曲所有精度结论，因此原始平台值、转换后值和回归结果都应进入证据包。

## 低频目标观测的滤波时间

目标跟踪消费请求式 RGB-D 观测时，用相邻接纳位置的采样时间差驱动滤波；
模型内 dt、状态转移 A 和过程噪声映射 B 必须一起更新，不能只改计时变量。
反馈定时器外推应从最后观测状态的副本计算，不反复推进观测滤波器。
先用固定 dt 对照锁定原算法，再检查变步长、无观测、失跟及重捕获。
YOPO-Tracker EKF 的固定步长状态/协方差对照已通过 atol=1e-10、rtol=1e-9；
这是迁移数值证据，不能替代真实移动目标精度。位置有效标志为 false 的检测
不能伪装为三维测量；状态协方差中的上游 Qt/Rt 仍是模型假设。

## Mission 的实际固定系与订阅处理能力

检测输出系应与真实自身 Pose 的固定系交叉核对；AS2 的某次部署发布 `earth`，
不能凭检测默认 `drone0/odom` 改写 Pose 标签。使用采样时刻 TF 将检测实际转换到
共同固定系，Mission 显式指定该系，并在发起 Tracking Goal 前等待自身 Pose 新鲜就绪。
目标先到而自身订阅尚未发现时，不放宽新鲜度；就绪等待仍受既定预算限制。

锁定 AS2 Python `DroneInterfaceBase` 的自动线程每个 spin 间隔只调用一次 spin_once。
默认20Hz可能不足以处理 clock、Pose、Twist、平台和Tracking反馈；先核对宿主实现，
通过其公开spin_rate参数配置处理能力，记录消息stamp、ROS now和接收墙钟年龄。
Mountains观察曾在默认处理频率下每约0.45s才消费一次反馈；提高处理频率后已观察到
多个独立采样和实际跟随点，但仍有真实检测失跟，不能据此宣称整轮可靠性通过。

宿主RPC依赖与模型环境分别加载。包含旧pydantic的宿主Python overlay会覆盖模型的
独立依赖；仅复用所需RPC包或在专用环境运行桥，模型worker保持自己的环境。
本轮实际出现过该依赖串扰失败，不通过重建共享镜像处理。

## 动态车辆附近的相机与物理净空

前视图顶部黑色遮挡与爬升后近场结构可能来自出生点上方的动态车辆。
结合实际机体pose和逐时碰撞对象判断；相机图像、Actor原点或ECC_Visibility
射线各自都不能独立证明飞行净空。Mountains实际顶部碰撞对象为装甲车，
不能误判为高度控制失效或仅相机自遮挡。
出生点移开后按实际高度/目标距离和垂直FOV检查目标画幅；本Demo原水平相机
在3m悬停时把6m前方皮卡截在底部，专属飞行配置改为-20deg俯角。
相机真实配置和桥的TF必须同源，保留原图与实际相机pose，不用图像裁切或假TF
代替物理视场修正。原地面配置与飞行配置分别保存，避免破坏已验证地面入口。

侧视出生点还需排除桥侧护栏：Mountains 的 X=3.5 候选出现桥体水平法线与
0.35m穿透，地面 PX4 检查无法稳定；X=2.6 实测仅桥面垂直接触并通过原生飞行。
这些数值仅适用于该场景。相机从 FRD(.3,0,-.3) 改为(.8,0,-.6)、pitch -55°
后实际侧面图移除机臂遮挡，但当前模型仍把车辆判为 microwave；完整入镜不保证识别。
类别诊断保留原阈值，在保存的真实输入上检查未经过业务类别过滤的全部类别框；
诊断标签不能重映射成车辆身份，也不能输入 Tracking 冒充支持。
物理相机 pose 与机体 pose/配置交叉核对后，再保存采样时刻实际 body→optical TF。
同时保留 RPC FOV 标量和渲染投影矩阵；本实例标量89.9036°，矩阵焦距320px
与配置90°/640×480一致，不能仅凭该标量差异认定 CameraInfo 错误。


## 分割可选时的框深度测量

接入 boxes-only 检测器前核对投影器是否强制读取实例 mask。保留原分割测量算法，
为框测量显式声明独立 policy 和输出 provenance；空 mask 不能变成矩形伪分割。
框内深度可能主要来自背景，先声明有效样本、前景支持、中心支持及周边背景分离
门槛，缺失或歧义时保留二维框并使位置无效。即使通过，也只能称可见表面测量，
不能据此宣称物体几何中心或三维真值。Detect 的 box_foreground_surface_v1 已通过
合成非恒等 TF 与失败回归；保存的真实皮卡深度因竞争簇被拒，尚无真实精度验收。
保存 RGB-D/TF 回放时保留原文件哈希与 frame；若重设测试 stamp 或保持某一录制 TF，
明确这是回放时序，不能把重复帧当作实时新测量或原始同步证据。


## 框内深度与受控初始视点（Mountains，2026-11-16）

无分割框的深度簇拒绝不等于存在两个真实物体。斜车身、车顶与开放货箱可产生
连续但跨度较大的光轴深度；先保存分布与空间分布，再区分连续表面、前景和背景。
固定宽度分箱可能将同一表面分成多簇，不能仅按异常文本解释为远距或无返回。
相机视角改善只证明可见性，仍需真实3D输出门。当前Mountains从已验证X2.6
后移到X6落到桥外低处，虽可相对起飞3m却看不到目标；修改出生点后须独立核对
地形/桥面、实际相机图和高度基准。回到X2.6、俯角−75度时DINO实时检出皮卡，
但现有深度策略仍拒绝，不能把该视角记录为已解决三维定位的推荐配置。

## 工具查询同时提供全局与本地状态

AS2 self_localization/pose可在earth，而规划器明确要求车辆odom。任务仅能调用Tool
时，由System等状态查询Tool分别返回原始全局pose和本地navigation_pose及各自新鲜度；
后者源自实际sensor_measurements/odom，不重写frame标签。检测用采样TF输出到规划
固定系，任务显式核对一致。启动阶段PX4可能重置本地高度，地图原点注册应在未解锁
状态稳定后执行；早期一帧有效位姿不证明适合冻结虚拟地面和地图原点。ROGMap
ORIGIN_AT_CORNER还会按inflation_step×inflation_resolution上移虚拟地面；配置应核对
实际解析后的地面值，稳定等待本身不能解决膨胀后位于地面以下的问题。

## 稀疏尺寸估距的时序平均

对尺寸先验估距加滤波时，保留原始位置、采样stamp及过滤诊断，最多混合单候选的
同固定系历史；多人不取平均，缺测/拒绝测量不重复输出旧值作为新观测。短窗局部
运动趋势对齐再平均可避免匀速运动的尾随平均滞后，但加速度响应和数据关联仍需验证。
历史窗口与目标有效期分开：历史可用于估计趋势，不能延长最后有效观测的时限。

先测真实有效观测间隔，再检查窗口能否凑齐最低样本数。WestStreet0.4s窗口在
0.2–0.45s间隔下始终预热，合成高频测试无法暴露；需有稀疏采样回归和实际
smoothed计数才能证明消费。0.8s/5帧在本场景已实际生效，随后仍因0.519s缺测
触发原0.5s门，属于连续追踪失败。平滑修正量不是对真值的精度改进。

## 最新帧生产/消费与时间缺口

连续观测用有界最新帧槽隔离采集与推理：采集回调只交换引用，单worker在锁外处理，
慢消费覆盖待处理旧帧而非排队。共享快照/流式入口时保留快照首帧与BUSY契约，
避免第二个采集订阅/模型worker。下游最新结果只消费一次，校验原stamp、接收年龄、
会话/时钟世代与生产者版本，不能用重复最新值刷新观测。

分别记录进入推理的输入stamp间隔与推理耗时；消除快照串行等待后若推理前仍有
大缺口，继续检查采集/传输/云台隔离，不能将buffer接通当成端到端连续性通过。
WestStreet真实流式轮仍有0.666s输入间隔而推理60–80ms，是该区分的失败证据。

原生发布频率需在ROS以前单独观测。ProjectAirSim Topic使用NNG Pair0单peer，
不可并接第二个SDK订阅者；需要时用透明转发记录原始stamp及转发耗时，保持
单条真实订阅链，且等场景加载客户端释放连接。比较各边界时取共同采样窗口、
唯一stamp与各自单调到达时间；配置上限、源时钟Hz与墙钟Hz分别报告。
Linux UDP诊断逐socket/inode读取drop与SO_RCVBUF，扫描/proc瞬时FD消失应只跳过
该FD，不可丢弃整个进程。已发布未接收仅定位区间，需socket证据或控制变量实验
才能归因为接收溢出。飞控未确认解除武装时保留所依赖的透明转发进程供恢复。

WestStreet 640×480 RGB真实对照：host接收上限约208KiB时DDS实际SO_RCVBUF为416KiB，
两个Python接收端有datagram drop，检测约4Hz；仅临时提高上限至4MiB、实际socket8MiB
后，原生→桥接收、桥放行→检测均无缺帧，检测约12.6Hz。此为该配置下的单变量
证据，不保证任意分辨率/负载的4MiB充分。缓冲小于一帧不自动证明溢出，需实际drop
与对照。系统参数恢复后后续运行会重新受原上限限制，应在部署准备中显式处理。

图像UDP接入的部署交付须包含宿主`net.core.rmem_max`、DDS请求值、实际SO_RCVBUF
与逐socket drop检查。配置请求大于内核上限时，在接收进程启动前显式准备环境，
重建socket后复核；提高上限不会自动扩容已有socket。host网络容器共享宿主限制。
不要将增大内核接收缓冲与应用层堆积旧图像混为一谈；前者吸收传输突发，后者仍
采用有界最新帧策略，并检查帧龄。内存开销按进程/机群评估，4MiB只是已验证配置
的起点。操作与真实对照摘要维护在
[公共DDS部署说明](../../deployment/airsim/config/dds/README.md#图像传输的宿主接收缓冲上限)。

短窗测量滤波遇到偶发多候选帧时，不混合候选，也不要无条件清空仍有效的历史：
重新预热的少量带噪点可能拟合出反向速度，继而连续拒绝正常运动范围内的后续观测。
WestStreet采用多候选旁路关联且不进入平均、近期历史按原时间规则过期；新增回归
和独立场景证明局部问题改善，但尺寸测距连续异常拒绝仍可使长期任务失败。
单候选历史本身不提供身份保证，应把身份/关联和测量平滑职责分别验证。

尺寸估距的可控残差可用源噪声模型加鲁棒降权处理，避免独立前置趋势门与跟踪门
重复拒绝。以归一化创新残差增大本帧Rt，限幅Kalman增益时同步用同一增益更新
协方差（如Joseph形式），验证单帧影响与连续偏差恢复；应用层不能把无观测、重复
采样或歧义身份包装成新观测。几何可达边界、噪声假设、关联歧义与真正缺测保护
单独声明。软更新回放通过不证明真值精度或真实控制下已充分激励该分支。

短时恢复必须区分“图像采样恢复”和“有效测量被消费”。用原采样stamp
匹配测距输出与Tracking消费时刻，恢复预算覆盖两者间延迟；预测输出使用
当前状态时间不表示观测已刷新，observation_stamp只能由有效关联测量推进。
恢复期间仍拒绝裁边身高框，不能为延长有效期把部分人物高度当完整身高。
