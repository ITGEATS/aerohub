# 构建操作规则

 多实例 CPU 推理不能把单实例线程设置直接乘到全部进程。先核对物理核数，再为 ROS executor、传感器、仿真和系统任务预留预算；将 ONNX、OpenMP、BLAS 等线程数做成显式配置。用全部实例同时运行时的处理率、最大间隔和系统负载选取配额，避免每个实例各自最快但整机超额分配。增加队列只能吸收有界抖动，不能替代线程预算；回调不应在持有生产队列锁时执行推理。

 远程启动长构建时记录客户端、远端 build 进程和 BuildKit executor 的归属。SSH 中断不保证远端 executor 已停止；重试前按 PID、命令、工作目录与启动时间核对，只终止本任务遗留的精确进程，避免多个大依赖下载并行或误伤其他构建。正式编排应使用可回收的进程组和有界清理。

 一次性 `docker run --rm -i ... -s` 从标准输入执行长准备脚本时，SSH/管道被中断也可能留下仍在运行的容器；`--rm` 只在容器退出后删除它。重试前必须按镜像、创建时间和工作区挂载精确查找容器，并检查容器内实际下载/编译进程。不得让两个准备容器并发写同一 venv、colcon workspace、wheel `.chunk` 或 `.partial`；发生并发写入后保留失败日志和下载缓存，但重新创建无法证明一致性的 venv/build/install 产物。启动脚本应优先为容器指定可追踪名称，并用 trap 或拥有者脚本收口。
