# 模型产物管理

ModelScope 用于分发 AeroHub 使用的模型权重、Houmo 编译产物和配套配置。每个模型一个仓库，模型内部按实际需要划分 `cuda/`、`houmo/`，共用文件留在根目录。组织审核期间可先使用个人账号，组织就绪后向组织仓库发布已校验的同一份文件。

## 环境与文件归属

上传、下载和发布管理使用仓库根 `.venv` 中的 ModelScope。模型推理仍使用各自的环境。共享工具依赖在根 [pyproject.toml](../pyproject.toml)，版本由 [uv.lock](../uv.lock) 锁定，准备方式见 [Python 环境说明](../README.md#python-environments)。

在仓库根目录执行以下命令。登录时在本机交互输入 Token，凭据由 ModelScope 保存在用户本机。

```bash
bash setup_python.sh
.venv/bin/modelscope login
.venv/bin/modelscope whoami
```

源码仓库中的模型 README 说明准备和运行方式，已有 `artifacts.json` 或校验清单记录来源、版本与文件哈希。发布材料进入 `artifacts/modelscope/<模型>/`，临时下载回验使用临时目录。按需复用已有清单格式。

## 准备一个模型

先定位实际文件，确认对应的上游提交、许可证与分发条件，再准备发布目录。例如 YOPO 的首批目录如下。

```text
yopo/
├── README.md
├── LICENSE
├── artifacts.json
└── cuda/
    └── epoch50.pth
```

发布材料包括以下内容。

- 原始权重或编译产物，以及加载所需的配置、词表、处理参数等配套文件。
- README 说明用途、后端、来源、适用运行环境、使用入口和实际验证范围。
- 原始许可证、版权声明及适用的第三方说明。
- 清单记录文件相对路径、大小、SHA-256、上游来源与版本。Houmo 产物还需记录目标板卡、编译工具链及运行时要求。

同一模型可以逐步补齐不同后端。云端模型在本地 README 记录服务绑定、配置和使用方式。模型已有的独立环境与准备入口见 [Inference 模型交付约定](../src/basic_function/inference/README.md#model-delivery)。

## 创建与上传

以下命令以 YOPO 首批仓库为例。发布其他模型时替换仓库 ID 和本地目录，并按实际许可与发布范围选择参数。执行前核对登录账号、目标仓库和材料内容。

```bash
.venv/bin/modelscope create popc0rn7/yopo \
  --repo-type model --visibility private --license mit

.venv/bin/modelscope upload popc0rn7/yopo \
  artifacts/modelscope/yopo \
  --commit-message 'Add pinned upstream YOPO checkpoint, provenance and MIT license'
```

已有仓库直接上传需要更新的材料。这里的上传目录只包含本次模型发布文件。

## 下载回验与版本接入

上传完成后，从远端下载到新目录，按发布清单逐个核对文件大小与 SHA-256。这样可以检查实际下载到的内容。示例中用临时目录回验 YOPO 权重。

```bash
verify_dir=$(mktemp -d /tmp/aerohub-yopo-verify.XXXXXX)
.venv/bin/modelscope download popc0rn7/yopo \
  --local-dir "$verify_dir" --total-timeout 120
sha256sum "$verify_dir/cuda/epoch50.pth"
```

正式接入前记录可固定引用的发布版本或提交。模型更新时保留既有部署所引用的版本。下载支持用 `--revision <版本或提交>` 指定目标，`setup.sh` 按本地清单下载缺失文件，校验通过后放入模型约定的位置，已有且校验通过的文件直接复用。非公开仓库需要下载用户具备相应访问权限。

回验记录保存仓库 ID、版本、文件哈希和结果。完成版本固定及准备入口接入后，再检查空缓存准备和模型加载。模型运行、ROS 接口及仿真验收结果分别记录在对应模型和 Demo 文档中。
