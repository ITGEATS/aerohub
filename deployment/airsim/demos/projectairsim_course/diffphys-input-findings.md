# DiffPhys 接管高度与输入对照发现

日期：2026-11-16。对象：ProjectAirSim 赛道 Demo，官方 DiffPhys `high_speed` / `base.pth`。

## 结论

静态离线实验发现，官方策略的竖直输出对深度图中的地面分布明显敏感。
在官方原生场景中，3～4 米处静止接管也能产生接近零或向下的推力；换成原版 SGM
深度没有消除异常。该结果不能归因于当前 AirSim 的理想深度，也不能仅用目标低一米解释。

已对照的预处理和机体水平坐标构造与上游一致，没有发现漏载权重。
这些证据不证明权重普遍损坏，也未确定完整训练原因。

本轮实验没有解决导航失败。经用户确认，赛道 Demo 改为原生 Takeoff **2 米**，
目标仍为地面测量原点相对 ENU **[0, 120, 3] 米**，速度仍为 5 m/s。
2 米起飞、3 米目标需要爬升，尚未进行该配置的飞行验收。

## 对照方法与结果

使用官方 `HenryHuYu/DiffPhysDrone` v1.0 的 `validation_code.zip`：

- 发布包 SHA256：`d894c0aded7de7f2d3d5f1c8bc8d0e32c23ccc24b130d1c115b5b9025a9adef5`。
- `base.pth` SHA256：`dd9ffeafd12e44dfd0e402fb880b52d110f414530faddb16e6c9b3dbd336bb64`。
- 四组发布飞行日志附带 checkpoint 与 `base.pth` 的所有参数张量完全相同。
- 对真实失败输入执行原始预处理，与当前接口的深度张量最大误差为 `2.98e-8`，action 最大误差为 `5.96e-8`。
- 64 组非恒等 roll/pitch/yaw 与非零机体速度，对照原始状态构造，最大误差为 `7.14e-7`。
- 毫米截断、图像翻转、planar/range 换算与水平目标等单因素实验，未消除原始失败输入的异常。

直接启动发布包中的 Flightmare 渲染器，在同一静态场景固定机体水平姿态和零速度，
扫描世界 z=1～5 米。相机采用上游 640×480、水平 FOV 91°、20° pitch、0.1 米双目基线。
scene_id=4、seed=69、世界 x=-20、y=20。使用原始 GPU SGM 核心处理真实双目图像，
按发布代码的无效视差规则和 uint16 毫米深度转换送入模型。SGM 临时探针仅去除 ROS1
传输和 NodeHandle 依赖，保留图像计算重载及 CUDA kernels。

下表固定纯水平目标速度为 **5 m/s**，GRU 初始状态为空，只比较第一帧。

控制检查沿用原门槛：推力方向 up_z≥0.5、归一化油门在 (0, 0.85]，没有放宽保护。
变化不单调，世界 z 也不等于任意地形下的离地高度，不能据此制定通用高度包线。
冻结图像和状态递推 GRU 仅为敏感性诊断，不代表动态飞行；首帧通过不证明稳定飞行。

第一个净竖直加速度为 -0.286865 m/s²，对应正常向上承重。其 launch 起飞高度为 2 米。
该 bag 未录制深度，不能直接重放原成功视觉输入。
